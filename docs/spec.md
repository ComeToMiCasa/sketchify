# postcss-sketchify MVP 명세

2026-10-21 작성 · Daniel Jung

## 개요

postcss-sketchify는 평범한 CSS를 읽어, 레이아웃은 그대로 두고 테두리와 채움을 손그림으로 바꾸는 빌드 타임 컴파일러다. 미리 만든 UI 키트가 아니라, 사용자가 쓴 스타일 정의를 변환하는 도구다.

- **타깃**: 손그림 콘셉트의 실제 서비스 페이지를 만드는 프론트엔드 개발자. 스케치 스타일은 항상 켜져 있고 토글은 없다.
- **레이아웃 불변**: 원래 border는 두께와 스타일을 유지하고 색만 transparent로 바꾼다. 요소의 크기와 위치는 1px도 바뀌지 않는다. 이 약속은 사용자 CSS 변환에만 적용하고, base 레이어는 제외한다.
- **클라이언트 JS 0**: 모든 그림은 빌드 때 SVG로 만들어 CSS에 넣는다.
- **성능 우선**: 남는 비용은 CSS 용량과 렌더링뿐이다. 용량을 키우는 선택(변형 수, 필압 길이, 크기를 아는 요소의 빗금, 색과 수정자 조합)은 문서에 비용을 밝힌다.

## 입력과 확장 계획

MVP의 입력은 순수 CSS이고, Tailwind는 다음 단계에서 지원한다.

- Sass와 CSS Modules는 PostCSS 단계에 도착할 때 이미 순수 CSS라 그대로 지원된다.
- Tailwind는 한 요소의 border, radius, 배경이 여러 클래스에 흩어져 있다. 그래서 내부 구조를 **읽기 → 요소별 스케치 정보로 모으기 → 출력** 세 단계로 나눈다. MVP의 모으기 단계는 "규칙 하나 = 요소 하나"를 기본으로 하고, Tailwind 확장 때 이 단계만 바꿔 끼운다.
- 런타임에 스타일을 만드는 CSS-in-JS(styled-components 등)는 범위 밖이다.
- 권장 사용 방식은 빌드 파이프라인의 PostCSS 플러그인이다. 개발 서버에서도 배포본과 같은 모습이 보여야 하기 때문이다. 배포 형태는 아래 '배포와 품질 기준'에 정리한다.

## 변환 범위

테두리, 채움, 한 변 선, 폼 요소를 손그림으로 바꾸고, 폰트와 그림자는 바꾸지 않는다.

| 대상 | 처리 |
| --- | --- |
| `border` (네 변 전체) | Rough.js 9-slice 테두리 |
| `border-top` 등 한 변, `hr` | 양 끝을 고정한 손그림 선 |
| `border-radius` | 테두리 모양과 모서리 조각 크기에 반영 |
| `background-color` | 채움 4종 중 하나 |
| 밑줄(`text-decoration`) | 줄마다 가로로 늘인 손그림 선 (M6 다음 단계) |
| 인풋, 텍스트박스, select | 요소 자체에 테두리, 색 고정 |
| 체크박스, 라디오 | 박스·원과 체크·점을 배경으로, 색 고정 |

- **폰트 교체는 제외**한다. 손글씨 웹폰트는 무겁고, 늦게 로드되면 글자 폭이 바뀌어 레이아웃이 밀린다(CLS). 폰트는 사용자가 직접 고르고 로딩 전략을 정한다.
- **box-shadow는 제외**한다. 원래 값 그대로 둔다.

## 테두리

Rough.js로 작은 사각형을 한 번 그려 9-slice 원본으로 쓰고, 요소 자체의 `border-image`로 그린다(A 방식). 모서리는 고정하고, 변은 길이 방향으로만 늘린다(`stretch`). 가상요소, `position`, `isolation`을 쓰지 않는다.

- **A 방식을 고른 이유**: 가상요소에 그리려면 요소에 `position: relative`와 `isolation: isolate`를 넣어야 한다. 그러면 바깥 조상을 기준으로 배치된 `absolute` 자식(메가 메뉴 등)의 기준이 바뀌고, 툴팁이 옆 요소 위로 올라가지 못한다. 비교 페이지에서 둘 다 실제로 깨지는 것을 확인했고, A 방식은 원본과 같았다.
- **9-slice를 고른 이유**: 통짜 SVG를 요소 크기로 늘이면 모서리가 찌그러지고 흔들림이 위아래로 과장된다. 짧은 조각을 반복하면 선이 주기적으로 구불거려 손그림답지 않다.
- **모서리 조각 크기**: 둥근 모서리는 곡선이 딱 들어갈 만큼만 쓴다(여백 4px + radius). 각진 모서리는 선이 교차하며 삐져나가는 여유를 남긴다(최소 14px). 작은 요소에서 브라우저가 모서리를 축소하지 않게 하기 위해서다.
- **선 두께**: 사용자가 정한 `border-width`를 그대로 그린다. Rough.js는 선을 두 번 겹쳐 그어 더 두꺼워 보이므로, 한 번의 두께는 0.85배로 줄인다. 4px 이상은 마커 느낌이 되지만 따로 보정하지 않는다.
- **레이아웃**: 원래 border는 두께와 스타일을 유지한 채 색만 transparent로 둔다. 선이 박스 밖으로 나가는 부분은 `border-image-outset`으로 그려 레이아웃에 영향이 없다.
- **색**: 색은 SVG에 고정된다. 컴파일러가 CSS에 쓰인 색마다 SVG를 만든다. `var()` 색은 컴파일러가 값을 찾을 수 있을 때만 쓸 수 있다(아래 "색 해석").
- **상태 규칙**: `:hover`, `:focus`처럼 색만 바뀌는 규칙은 같은 모양을 그 색으로 그린 SVG로 `border-image-source`만 바꾼다. 모양은 그대로라 선이 튀지 않는다. 처음 바뀔 때 테두리가 비는 문제는 없음을 확인했다.
- **색 해석**: 리터럴 색은 그대로 쓴다. `var()`는 같은 파일의 `:root` 등에서 값을 찾아 쓰고, 미디어 쿼리(다크 모드 등)에서 값이 바뀌면 그 안에 변형 SVG를 따로 만든다. 빌드 때 값을 알 수 없는 색은 컴파일 오류다(아래 "제약과 오류 처리").
  - **변수를 찾는 곳**:
    - 같은 파일에서 셀렉터가 `:root`, `html`, 또는 그 둘로만 된 목록인 규칙(루트 규칙). `@layer` 안도 밖과 똑같이 보고 순서만 따른다. `:host`는 루트가 아니다.
    - 테두리를 쓴 규칙 자신. 이 정의가 루트 값을 이긴다(요소 자신의 값이 물려받은 값을 이기므로).
    - 셀렉터에 그 규칙(부모)이 들어 있는 수정자·상태(`.btn.btn--primary { --ink: … }`). "여러 규칙에 걸친 테두리"의 캐스케이드로 정한다(M4).
    - 그 밖의 규칙(`html.dark`, `.theme-x` 등)이 바꾸는 변수는 클래스 테마로 보고 컴파일 오류다.
  - **풀리는 범위**: `var()`는 색뿐 아니라 테두리 선언 전체(`border*`, `border-radius`)에서 푼다. `border: 1px solid var(--ink)`처럼 단축 속성에 변수가 있으면 풀어야 두께와 스타일도 알 수 있다. 대체값(`var(--x, red)`)과 변수 안의 변수도 푼다.
  - **조건 변형**: `@media`·`@supports` 안의 루트 규칙이 값을 바꾸면 조건마다 따로 푼다(기본값 위에 그 조건의 값을 덮어씀).
    - 결과 그림이 기본과 다를 때만 그린 규칙 바로 뒤에 같은 조건으로 감싼 덮어쓰기 규칙을 넣는다. 예: `@media (prefers-color-scheme: dark) { .card { <칸 변수 12개>; border-image: … } }`
    - 같은 셀렉터이고 소스에서 뒤에 오므로, 조건이 맞을 때만 이긴다. 원래 규칙이 `@media` 안에 있으면 그 안에 중첩한다.
    - 모양(seed, 뒤집기 칸)은 같고 색만 다르다.
    - 그 조건에서 색이 `transparent`가 되면 덮어쓰기 규칙은 `border-image: none`이다.
  - **알려진 한계**:
    - 두 조건이 동시에 맞을 때(다크 + 고대비 등)의 겹침은 따로 풀지 않고 조건마다 독립으로 푼다.
    - `@layer`의 우선순위는 변수 값을 정할 때 무시한다.
    - 다른 파일의 변수는 찾지 않는다. postcss-import 등으로 합친 뒤 변환해야 한다.
- **출력 형태**: 원래 테두리 선언은 그대로 두고, 그 규칙의 마지막 테두리 선언(두께·스타일·색을 정하는 선언) 바로 뒤에 `border-color: transparent`, 이웃 변형 칸 변수 12개(`--sk-{seed}-{뒤집기}: var(--sk-<그림>)`), `border-image: var(--sk) C / Cpx / <outset>px stretch`를 넣는다. 원래 선언 중 하나라도 `!important`면 넣는 선언도 모두 `!important`다. 그림 자체와 고르는 규칙은 파일 맨 앞에 한 번만 둔다(아래 "이웃 요소 변형").
- **트레이드오프**: 실행 중에 JS로 색 변수를 바꾸는 테마 기능은 테두리에 반영되지 않는다. 색 조합만큼 SVG가 늘지만, 색만 다른 SVG는 압축이 잘 돼 brotli 기준 전송량 차이는 거의 없다.

### 그리는 테두리와 그대로 두는 테두리

요소에 걸리는 규칙들(한 규칙, 또는 부모와 수정자·상태 등 "여러 규칙에 걸친 테두리")에서 네 변의 두께·스타일·색과 모서리를 모두 알 수 있을 때 그린다. 알 수 없거나 표현할 수 없으면 원래 CSS대로 둔다. 경고(아래 "제약과 오류 처리")는 M8에서 추가한다.

| 경우 | 처리 |
| --- | --- |
| 네 변 두께가 같은 px(`thin`·`medium`·`thick` = 1·3·5px 포함), 스타일이 모두 `solid`, 색이 모두 같은 리터럴 색 | 그림 |
| 위 값이 `var()`로 쓰였고 같은 파일에서 풀 수 있음("색 해석") | 풀어서 그림. 조건마다 값이 바뀌면 조건 변형도 그림 |
| 위 조건을 다 갖추었는데 색만 `currentColor`(색을 생략한 단축 속성 포함), 또는 테두리 선언의 `var()`를 풀 수 없음 | 컴파일 오류 ("제약과 오류 처리") |
| 규칙에 `--sketch: off` | 그대로 둠, 오류 없음, 이 선언은 출력에서 지움 |
| `border` 단축 속성에서 두께 생략 | CSS 규칙대로 `medium`(3px)로 그림 |
| 한 규칙 안에서 같은 속성을 여러 번 씀 | CSS처럼 뒤에 오는 선언이 이김 |
| `@media`·`@supports`·`@layer` 안의 규칙 | 일반 규칙처럼 그림 |
| `border-radius`가 네 모서리 같은 px이고 32px 이하 | 그 radius로 그림. radius가 없으면 각진 모서리 |
| radius가 32px보다 큼(알약·원) | 그리지 않고 원래 CSS 테두리로 보여줌. 요소 크기를 모르므로 모서리 조각이 요소보다 커져 그림이 거의 사라지기 때문(M4에서 정함). 알약·원 손그림은 이후 과제 |
| `solid`가 아닌 스타일(dashed, dotted, double, groove, ridge, inset, outset) | 그대로 둠 |
| radius가 %, 모서리마다 다름, 타원(`/`) | 그대로 둠 |
| 두께 0, `none`·`hidden`, 색 `transparent` | 그대로 둠 (그릴 선 없음) |
| 전역 키워드 색(`inherit` 등) | 그대로 둠 |
| 정확히 한 변에만 선이 있음(`border-bottom`, `hr`의 `border-top` 등) | 한 변 선으로 그림("한 변 border, hr, 밑줄"). 그 변에 닿는 두 모서리가 둥글면 원래 CSS 테두리로 둠 |
| 두세 변에만 선이 있음(위+아래, ㄱ자 등) | 원래 CSS 테두리로 둠. 경고는 M8 |
| 테두리 일부만 바꾸는 규칙(부분 규칙) | 셀렉터에 부모가 있으면 "여러 규칙에 걸친 테두리"대로 그림, 없으면 컴파일 오류. 모서리만 바꾸는 규칙은 부모가 없으면 그대로 둠 |
| 두께가 em·rem 등 px가 아닌 단위, 변마다 다른 값, 논리 속성(`border-inline-*` 등) | 그대로 둠 |
| 사용자가 이미 `border-image*`를 쓴 규칙, `@keyframes` 안 | 그대로 둠 |

## 한 변 border, hr, 밑줄

선 하나짜리 요소도 테두리와 같은 원리로, 양 끝은 고정하고 가운데만 길이 방향으로 늘인다.

- **한 변 border와 hr**: 짧은 Rough.js 선을 원본으로, 해당 변에만 `border-image` 너비를 준다. 양 끝 16px은 고정하고 가운데만 늘인다. 원본을 비율째 늘이면 양 끝 여백까지 늘어나, 긴 목록에서 구분선이 양쪽 13px씩 짧아진다.
- 선이 요소 끝까지 닿도록 `border-image-outset`으로 남은 여백을 상쇄한다.
- **대상**(M5): 정확히 한 변에 선이 있고(두께 > 0, `solid`, 리터럴 색, 변수 해석 포함) 나머지 세 변은 선이 없는 테두리다(두께 0, `none`/`hidden`, 또는 정하지 않음).
  - 블록과 인라인 요소 모두 대상이다. 여러 줄로 감기는 인라인 요소(링크의 `border-bottom`)는 기본 `box-decoration-break: slice`대로, 선 하나가 줄 조각마다 나뉘어 그려진다.
  - 그 변에 닿는 두 모서리가 둥글면 그리지 않고 원래 CSS 테두리로 둔다. 반대쪽만 둥근 탭(`border-radius: 6px 6px 0 0` + `border-bottom`)은 그린다.
  - 두세 변에만 있는 테두리는 원래 CSS 테두리로 둔다.
  - `hr`은 사용자 CSS에 한 변 테두리로 쓴 경우(`hr { border: 0; border-top: 1px solid … }`)만 그린다. 브라우저 기본 `hr`은 `@sketchify base`(M7)에서 다룬다.
- **출력**: 원본은 길이 152px(양 끝 16 + 가운데 120), 두께 방향 W + 10px의 선 하나다. 휨은 테두리의 1.5배다. `border-bottom`이면:
  - `border-image: <그림> 0 16 H 16 / 0 16px Hpx 16px / Hpx 3px ((H−W)/2)px 3px stretch`
  - 좌우 outset 3px은 선 끝을 요소 끝에 맞춘다.
  - 아래 outset은 선 가운데를 원래 테두리 가운데에 맞춘다.
  - 위(그림 없는 반대쪽) outset H는 얇은 요소에서 그림이 줄어들지 않게 영역을 넓힌다.
  - 다른 변도 같은 방식이다. 이웃 변형(seed 3 × 뒤집기 4)과 조합 규칙(예: `.list li:hover { border-bottom-color }`)은 테두리와 같다.
- **밑줄**: 여러 줄로 감기는 텍스트를 따라가야 해서 배경으로 그린다. 줄 조각마다 가로로 늘이고(`box-decoration-break: clone`), 색은 SVG에 고정한다.
  - `text-decoration` 밑줄은 M6(채움) 다음으로 미뤘다(M5에서 사용자 결정). 배경 겹치기, `background` 단축 속성이 그림을 지우는 문제, 색(대개 생략된 `currentColor`)을 채움과 함께 풀어야 하기 때문이다.

## 채움

MVP 채움은 단색, 거친 단색, 빗금, 형광펜 네 가지다. 단색은 원래 `background-color`를 그대로 두므로 `var()` 색도 그대로 동작한다. 나머지는 색을 SVG에 고정한다.

| 방식 | 구현 (A 방식) | 특징 |
| --- | --- | --- |
| 단색 | 원래 `background-color` 그대로 | SVG 없음, 변수 색 동작 |
| 거친 단색 | 테두리와 같은 SVG에 울퉁불퉁한 채움을 함께 그려 `border-image`의 `fill`로 | 테두리·채움 색 조합마다 SVG |
| 빗금 | 반복 무늬를 `background-image`로, `background-clip: padding-box` | 손맛이 가장 강함, 글자 뒤에선 산만할 수 있음 |
| 형광펜 | 테두리와 같은 SVG에 함께 그려 `border-image`의 `fill`로, 바깥으로 나가는 부분은 outset | 큰 면적엔 어색 |

요소 바깥으로 나가야 하는 채움은 배경으로 그릴 수 없으므로(배경은 border box 안에만 칠해짐), 테두리의 `border-image` SVG에 합친다.

채움 방식은 규칙마다 `--sketch-fill: solid | rough | hatch | marker`로 지정한다. 지정하지 않으면 단색이다. 테두리 없이 채움만 있는 요소(진행 막대 안쪽 막대 등)도 일반 요소와 똑같이 처리한다.

빗금은 바탕색 없이 선만 긋는다. 선은 거의 곧고, 선마다 굵기와 휨이 조금씩 다르며, 한 선 안에서 필압이 천천히 변한다. 진하기 변화는 두지 않는다.

- **크기를 아는 요소**: Rough.js처럼 선마다 요소 경계와 만나는 두 점을 계산해 그 사이에 선을 긋는다. 끝은 진행 방향에 수직이고, `taper`(가늘게 모임)와 `square`(네모) 중 고르며 기본은 네모(square)다. 끝나는 위치는 선마다 테두리 선 중심과 바깥 4px 사이에서 다르다. 바깥으로 나가야 하므로, 테두리와 빗금을 한 SVG에 그려 `border-image`로 적용한다.
- **크기를 모르는 요소**: 끊김 없는 긴 빗금을 배경으로 깔고, 패딩 상자 안에서만 보이게 한다. 테두리 바깥으로 나가지 않고, 페이드아웃은 쓰지 않는다.
- 크기를 모르는 요소의 펜 끝 처리는 이후 버전에서 Houdini `paint()`로 보강한다.

시도했다가 뺀 것: 어긋난 단색, 교차 빗금, 점, 옅은 바탕색을 깐 빗금, 짧게 끊긴 빗금, 끝을 흐리게 하는 페이드, 타일을 요소에 맞춰 늘이는 방식(`round`, 이음매와 물결 발생).

## 폼 요소와 @sketchify base

폼 요소도 다른 요소와 같은 A 방식(요소 자체의 `border-image`)으로 그린다. 가상요소를 못 붙이는 요소여서 생기던 차이가 없어졌다.

- **인풋, 텍스트박스, select**: 테두리를 요소 자체의 `border-image`로 그린다. `:focus`에서 색이 바뀌면 같은 모양의 SVG를 색만 바꿔 하나 더 만든다.
- **select**: `appearance: none`으로 기본 화살표를 지우고 손그림 화살표를 그린다. 펼쳐지는 옵션 목록은 브라우저 기본 모양 그대로다.
- **체크박스, 라디오**: `appearance: none`으로 기본 모양을 지우고, 배경에 박스·원과 체크·점을 그린다. `:checked`일 때 배경을 바꾼다.
- **포커스 링 유지**: 키보드 사용자를 위해 포커스 표시가 가려지면 안 된다.
- **`@sketchify base;`**: 이 한 줄이 있는 자리에 폼 요소와 hr의 기본 스케치 스타일을 넣는다. `@layer`와 `:where()`로 우선순위를 0으로 만들어, 사용자 스타일이 어디에 있든 항상 이긴다.
- base는 사용자 CSS를 변환하는 게 아니라 브라우저 기본 모양을 대체하므로, 레이아웃은 "브라우저 기본 크기에 최대한 가깝게"까지만 보장한다.

## 이웃 요소 변형

같은 셀렉터라도 이웃한 요소끼리, 그리고 다른 곳에 있는 비슷한 요소끼리도 모양이 달라야 한다. (자기 순번 + 부모 순번 + 조부모 순번)으로 원본을 고르고, `:nth-child`로 섞는다.

- 원본은 seed가 다른 3개(11, 23, 37)다. 뒤집기는 요소 자체를 뒤집으면 글자도 뒤집히므로, SVG 안에서 `<g transform>`으로 뒤집은 변형(원본·좌우·상하·둘 다)을 따로 만든다. 그림 하나가 12장이 된다.
- 원본 그림은 CSS 변수에 한 번만 넣고, 고르는 규칙은 어떤 변수를 쓸지만 정한다. 고르는 규칙이 수십 개라도 용량은 거의 늘지 않는다.
- **출력 구조**:
  - 파일 맨 앞(`@charset`·`@import`·`@layer a, b;` 문 뒤)에 `:root { --sk-<해시>: url(…); … }`로 그림을 한 번씩 넣는다.
  - 그 뒤에 고르는 규칙 22개를 둔다:
    - 기본값 `:where(*)` 하나
    - 자기 순번 mod 4로 뒤집기를 고르는 규칙 3개
    - (자기 + 부모 + 조부모 순번) mod 3으로 seed를 고르는 `:nth-child(3n+…)` 규칙 18개
  - 그리는 규칙은 자기 그림 12장을 칸 변수 `--sk-{seed}-{뒤집기}`에 넣고 `border-image: var(--sk)`로 그린다.
  - 고르는 규칙은 셀렉터를 모르고 모든 요소에 "몇 번 칸"만 정한다. 변수의 `var()`는 요소마다 풀리므로 요소마다 자기 규칙의 그림이 골라진다. 그래서 복잡한 셀렉터, 상태 규칙, 미디어 쿼리 안 규칙에도 따로 손대지 않고 섞인다.
  - 완성된 상태 규칙(`.btn:hover { border: … }`)은 같은 칸의 다른 색 그림을 쓰므로 모양은 그대로다.
  - 조부모가 없는 얕은 요소는 기본값(seed 0, 뒤집지 않음)을 쓴다.
- **그림 변수 이름**: `--sk-` 뒤에 그림 내용의 FNV-1a 32비트 해시 8자리를 붙인다. 순번 이름은 따로 컴파일한 CSS 파일끼리 같은 이름으로 서로 덮어쓰기 때문이다. 칸·선택 변수 이름은 `--sk`, `--sk-0`~`--sk-2`, `--sk-{0..2}-{0..3}`이다.
- **가상 요소**: `::before` 등 가상 요소를 고르는 규칙은 섞지 않고 seed 0의 뒤집지 않은 그림을 `border-image`에 바로 쓴다. 가상 요소는 고르는 규칙에 걸리지 않고, 요소의 선택을 물려받으면 엉뚱한 그림이 나올 수 있다.
- 그린 규칙이 없는 파일에는 아무것도 덧붙이지 않는다.
- **용량** (M2 측정, 테스트 페이지 5개 합계, KB, 원본 / gzip / brotli):
  - 그림 1장: 24.9 / 6.7 / 5.3
  - seed 3장: 64.5 / 13.6 / 10.6
  - seed 3장 × 뒤집기 4방향: 219.1 / 18.5 / 13.5
  - 뒤집기 4방향은 seed 3장 대비 brotli +27%(+2.9KB)다. 테두리 종류가 많은 페이지는 +42%(+1.3KB)까지 늘었다. 압축 전 크기는 3.4배다. 늘어난 양의 일부는 그림이 아니라 규칙마다 붙는 칸 변수(압축이 잘 안 되는 해시 이름)다. 절대량이 작아 4방향을 유지하고, M8 용량 보고에서 다시 본다.
- 테두리뿐 아니라 인풋·select·텍스트박스, 체크박스·라디오, 아바타(원)에도 같은 규칙을 적용한다.
- 변형 규칙은 `:where()`로 감싸 우선순위를 올리지 않는다. 요소별 정밀 규칙(크기를 아는 요소의 빗금 등)은 변형 규칙보다 반드시 이겨야 한다.
- 요소마다 고유한 seed는 MVP 범위 밖이다. 이후 JSX 플러그인이나 SSR로 확장한다.

## 옵션

옵션은 전역으로만 받는다. 규칙별 덮어쓰기는 MVP 범위 밖이다.

**거칠기**(`roughness`)는 프리셋 이름이나 0 이상의 숫자로 받고, 기본은 `normal`이다. 숫자를 받으면 `roughness`로 쓰고, 휨과 삐침은 프리셋 사이를 선형 보간해 정한다. 0.6·1.3·2.4는 subtle·normal·messy와 정확히 같고, 이 범위 밖은 양 끝 구간의 기울기로 연장하되 0 아래로 내려가지 않는다. 그 밖의 값은 컴파일 오류다.

| 프리셋 | roughness | bowing | 삐침 |
| --- | --- | --- | --- |
| subtle | 0.6 | 0.6 | 1.2 |
| normal (기본) | 1.3 | 1.2 | 2 |
| messy | 2.4 | 2.2 | 3 |

**빗금**은 아래 값을 기본으로 한다.

| 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `gap` | 6px | 선 간격 |
| `weight` | 1.9px | 선 굵기 중앙값 |
| `weightJitter` | ±0.25px | 선마다 굵기 차이 |
| `pressure` | ±16% | 한 선 안의 필압 변화 폭 |
| `pressureLength` | 136px | 필압이 한 번 굵어졌다 가늘어지는 길이 |
| `bow` | 0.5px | 선의 완만한 휨 |
| `ends` | square | `taper` 또는 `square` |
| `over` | 4px | 크기를 아는 요소에서 테두리 밖으로 나갈 수 있는 거리 |

- `gap`은 내부 반복 그림의 크기를 나눠떨어져야 선이 이어진다. 안 맞는 값이 들어오면 컴파일러가 반복 그림 크기를 맞춘다.
- `pressureLength`를 늘리면 반복 그림이 커지고 CSS 용량도 늘어난다. 문서에 이 비용을 안내한다.
- 옵션 설명에는 "타일" 같은 내부 개념 대신 결과로 보이는 것(간격, 필압 길이)만 쓴다.

## 크기 처리

컴파일러는 요소의 실제 크기를 모른다. 그래서 대부분은 크기와 무관하게 그려지는 구조로 해결하고, 크기를 아는 요소만 정밀하게 그린다.

- **테두리, 한 변 선, 거친 단색·형광펜 채움**: 9-slice로 크기와 무관하게 질감이 일정하다.
- **빗금(크기를 모르는 요소)**: 192px짜리 그림을 바둑판처럼 반복한다. 선이 반복 경계를 넘어 끊김 없이 이어지도록, 간격·휨·필압을 반복 크기 주기로 맞춘다.
- **크기를 아는 요소**: 규칙에 px로 쓴 `width`·`height`(border-box 기준)나 `--sketch-size: W H` 힌트가 있으면 크기를 아는 것으로 본다. 빗금을 선마다 계산해 정밀하게 그리는 데 쓴다. 요소마다 SVG가 하나씩 생겨 용량이 늘어난다.
- headless 브라우저로 실제 크기를 재는 방식은 MVP 범위 밖이다.

## 배포와 품질 기준

PostCSS 플러그인을 본체로 하고, CLI는 그 위에 얇게 씌운다. 지원 브라우저는 Chromium 계열과 Safari다.

- **PostCSS 플러그인**: 개발 서버에서도 배포본과 같은 모습이 보여야 하므로 기본 사용 방식이다. Vite, Next.js, webpack, Parcel은 `postcss.config.js`를 읽으므로 도구별 플러그인은 만들지 않는다.
- **CLI**: 플러그인을 감싼 얇은 도구다. 빌드 도구 없는 정적 사이트와 빠른 시험용이다. 플러그인과 같은 설정 파일(`sketchify.config.js`)을 공유한다. 프로토타입에 있던 폰트 관련 옵션은 없앤다.
- **중복 제거**: PostCSS는 CSS 파일을 하나씩 따로 처리한다. MVP는 한 파일 안에서만 같은 그림을 CSS 변수에 한 번 넣어 재사용한다. 파일 간 중복 제거는 이후 과제다.
- **지원 브라우저**: Chromium 계열(Chrome, Edge, Samsung Internet 등)과 Safari. Safari에서 동작하는 것을 확인했다. iOS의 모든 브라우저는 WebKit을 쓰므로, Safari 지원으로 iPhone·iPad도 범위에 들어온다. Firefox는 범위 밖이다.
- **지원 Node**: 20 이상(`engines: ">=20"`). 개발 도구(tsup, vitest)도 Node 20에서 도는 버전을 쓰고, CI는 Node 20으로 돌린다.
- **용량 예산 (제안)**: 빌드를 실패시키지 않고 경고만 한다. 출력 파일마다 늘어난 크기(원본, gzip)를 보고하고, 예산을 넘으면 크게 기여한 규칙을 함께 알려준다. 기본 예산은 실제 페이지로 보정해 정한다.

## 제약과 오류 처리

빌드 때 색을 알 수 없으면 컴파일을 실패시키고, `border-image`로 표현할 수 없는 경우는 경고한다.

| 경우 | 처리 |
| --- | --- |
| `currentColor` 테두리·채움 (색을 생략한 `border: 1px solid` 포함) | 컴파일 오류 |
| 값을 정적으로 찾을 수 없는 `var()` | 컴파일 오류 |
| 클래스로 바꾸는 테마 변수(`html.dark { --ink: … }` 등). 테두리가 쓰는 변수(변수 안의 변수 포함)를 루트 규칙도, 그 규칙 자신도, 셀렉터에 그 규칙(부모)이 들어 있는 규칙도 아닌 규칙이 정의하면 해당 | 컴파일 오류 |
| 테두리 일부만 바꾸는데 셀렉터에 부모가 없는 규칙("여러 규칙에 걸친 테두리") | 컴파일 오류 |
| 부분 규칙의 셀렉터에 후보가 여럿인 `:is()`·`:where()` | 컴파일 오류 |
| 한 부모에 걸리는 규칙(수정자·상태·조건)이 16개 초과 | 컴파일 오류 |
| 조건(`@media` 등) 안에서 바뀐 값으로는 그릴 수 없는 테두리(실선이 아니게 되는 등) | 컴파일 오류 |
| `--sketch`에 `off`가 아닌 값 | 컴파일 오류 |
| `border-collapse: collapse`인 표 | 경고 |
| 변마다 다른 색이나 스타일 | 경고 |
| `dashed`, `dotted` 테두리 | 경고 |
| `transition: border-color` (그림이 한 번에 바뀜) | 경고 |
| 부모의 `overflow: hidden`·`auto`가 바깥으로 나간 선을 자름 | 경고 |

**여러 규칙에 걸친 테두리.** `border-image`는 두께, 모서리, 색을 그림 하나에 담는다. 원래 CSS는 속성마다 이기는 규칙이 따로지만, 그림은 이기는 규칙 하나가 통째로 정한다. 그래서 테두리를 여러 규칙에 나눠 쓴 경우 컴파일러가 결과를 미리 계산한다.

- **원칙: 원래 CSS가 낼 결과를 그린다.** 한 요소에 함께 걸릴 수 있는 규칙들(부모, 수정자, 상태, `@media` 안 같은 셀렉터)의 조합마다, 각 테두리 속성을 원래 CSS의 캐스케이드(중요도 → 우선순위 → 소스 순서)로 정해 그린다. 사용자 정의 속성도 같은 캐스케이드로 정한 뒤 `var()`를 푼다.
- **부모**: 스스로 테두리를 다 정하는 규칙 P(네 변 완성, 또는 `border-bottom: 1px solid red`처럼 한 변 완성. 반쯤 정한 변이 없는 규칙)가 다음을 모두 만족하면 규칙 R의 부모다(한 변 규칙은 M5에서 추가). 부모는 셀렉터로만 정하고, 작명 관례(BEM 등)로 추측하지 않는다.
  - P의 마지막 복합 셀렉터(클래스·타입·속성·가상 클래스)가 R의 것에 모두 들어 있다(`.btn` ⊂ `.btn.btn--lg:hover`).
  - P에 앞 문맥이 없거나 R과 같다. `.toolbar .btn`은 `.btn`에서 받고, 조합 규칙도 문맥을 유지한다.
  - 가상 요소가 같다.
  - 조건(`@media` 등) 안의 P는 그 조건 안의 R에만 부모다.
  - 같은 부모 아래 규칙들이 한 "묶음"이다. 셀렉터 분석은 postcss-selector-parser로 한다.
- **부분 규칙**: 어떤 변의 두께·스타일·색 중 일부만 정하는 규칙(`border-color: red`, `border-width: 0`)이다. 변 단축 속성으로 그 변을 다 정하는 한 변 규칙(`border-bottom: 1px solid red`)은 부분 규칙이 아니다(M5).

| 경우 | 예시 | 처리 |
| --- | --- | --- |
| 같은 셀렉터 | `.btn:hover`, `@media { .btn { … } }` | 원래 규칙에서 받아옴 |
| 셀렉터에 부모가 들어 있음 | `.btn.is-large`, `.btn.btn--large`, `.toolbar .btn` | 부모 규칙에서 받아옴 |
| 셀렉터에 부모가 없는 부분 규칙 | `.btn--large`, `.w2 { border-width }`, `.x { border-color }` | 컴파일 오류. 이름은 보지 않는다 |
| 모서리만 바꾸는 규칙, 부모 없음 | `.rounded { border-radius: 8px }` | 그대로 둠(테두리 없는 요소에도 흔함) |
| 셀렉터 목록 | `.a:hover, .b:hover { border-color }` | 셀렉터마다 따로 받아옴. 그림이 다르면 원래 규칙 뒤에 셀렉터별 규칙으로 나눠 씀 |
| 후보가 여럿인 `:is()`·`:where()` | `:is(.a, .b):hover { border-color }` | 컴파일 오류(목록으로 풀어 쓰라고 안내) |
| 셀렉터에 부모가 있는 규칙의 변수 | `.btn.btn--primary { --btn-ink: blue }` | 테두리 값을 바꾸는 것과 같게 보고 받아옴 |

- 오류 메시지는 세 가지 해결책을 안내한다: 셀렉터에 부모를 포함(`.btn.btn--large`), 그 규칙에 테두리 속성(두께, 스타일, 색, 모서리)을 모두 쓰기, `--sketch: off`.
- `border` 단축 속성이 있는 규칙에는 항상 그 뒤에 `border-image`를 다시 쓴다.
- **조합 규칙은 자동으로 만든다.** 수정자끼리뿐 아니라 상태(`:hover` 등), `@media` 안 같은 셀렉터 규칙도 조합 대상이다.
  - 지금 이기는 그림(각 규칙의 그림과 먼저 만든 조합)이 원래 CSS의 결과와 다를 때만 만든다. 예:
    - 같은 속성을 바꾸는 수정자·상태끼리(`.btn--primary`와 `:hover`, 둘 다 색)는 조합하지 않는다. 원래 CSS처럼 나중 규칙이 이긴다.
    - 크기 수정자와 `:hover`는 조합한다(`.btn.btn--lg:hover`).
    - `@media (…) { .btn { border-radius } }`와 색 수정자는 그 조건 안에 조합한다(`@media (…) { .btn.btn--primary }`). `.btn--lg`처럼 자기 모서리를 정하는 수정자는 원래 CSS에서도 이기므로 조합하지 않는다.
  - 셀렉터는 구성원 셀렉터를 합친 것이라 우선순위가 구성원 이상이다. 소스에서 가장 뒤 구성원 규칙 바로 뒤에, 같은 `@media`·`@layer` 안에 넣고, 다른 구성원의 조건은 감싼다(중첩 규칙이면 가장 바깥 규칙 뒤에 전체 셀렉터로).
  - 같은 우선순위끼리는 가장 뒤 구성원의 순서를 따라, 상태 두 개가 겹치면 원래 CSS처럼 나중 규칙이 이긴다.
  - 결과에 쓰인 테두리 선언 중 `!important`가 있으면 조합도 `!important`다. 부모가 `!important`면 원래 CSS처럼 부모 값이 이긴다.
  - 조합 규칙도 칸 변수 12개를 쓰므로 같은 요소는 수정자·상태가 바뀌어도 같은 모양이다. 조건(다크 모드) 덮어쓰기도 붙는다.
- **그릴 수 없는 조합 결과**(`border-style: none`, `dashed`, 변마다 다른 색, 큰 radius 등): 그 조합에 `border-image: none`과 결과 색을 넣어 원래 CSS처럼 보여준다. 경고는 M8.
- 한 부모의 구성원이 16개를 넘으면 컴파일 오류다(조합이 2^n으로 늘어남).
- 조합 수만큼 그림이 늘어난다. 용량 예산 경고에 조합으로 늘어난 그림 수와 크기를 따로 보여준다(M8).
- **알려진 한계**:
  - 앞 문맥이 서로 다른 구성원끼리(`.toolbar .btn`과 `.sidebar .btn`)는 조합하지 않는다.
  - 다른 묶음의 규칙이 한 요소에 함께 붙는 경우(`.btn`과 `.card`)는 셀렉터에 둘 다 쓰지 않으면 알 수 없어 조합하지 않는다. M8 경고 대상이다.
  - `@layer` 우선순위는 계산하지 않는다(순서만 따름).

- 오류 메시지는 줄 번호와 함께, 명시적인 색을 쓰거나 `--sketch: off`로 그 규칙을 빼는 방법을 안내한다. 색을 생략하면 `currentColor`가 된다는 점도 설명한다.
  - 변수 오류에는 정의할 곳(`:root`, `html`, 그 규칙)과 "다른 파일은 postcss-import로 합치기"를 함께 안내한다.
  - 클래스 테마 오류에는 값을 바꾸는 규칙의 위치와 미디어 쿼리로 바꾸는 예를 함께 안내한다.
  - 오류는 모아서 한 번에 낸다. 위치는 첫 오류를 가리키고, 여러 개면 각 오류를 `줄:열`과 함께 나열한다.
- **`--sketch: off`**: 이 선언이 있는 규칙은 그리지 않고 그 규칙의 오류도 내지 않는다. 출력에서는 이 선언을 지운다. `off` 말고 다른 값은 아직 없다.
- **알려진 제약 (MVP에서 대응하지 않음)**: Windows 고대비 모드(`forced-colors`)에서는 테두리 색이 시스템 색으로 바뀌지 않고 그림 색 그대로 남는다.

## 구현 주의점

데모를 만들며 실제로 겪은 문제들이다. 컴파일러에서도 똑같이 생길 수 있어 규칙으로 남긴다.

| 문제 | 규칙 | A 방식에서 |
| --- | --- | --- |
| `border` 단축 속성이 `border-image`까지 초기화함. 뒤에 오는 규칙(예: `:hover { border: … }`)도 그림을 지움 | `border` 단축 속성이 있는 모든 규칙에서, 그 뒤에 `border-image`를 다시 쓴다 | 새로 생김 (테스트 중 발견) |
| 선 SVG를 100% 너비로 늘이면 기본값이 비율을 유지해 가운데만 그려짐 | `preserveAspectRatio="none"` 또는 3-slice | 적용 (밑줄) |
| Chrome이 `hr`을 기본으로 잘라냄 | `hr`에 `overflow: visible` | 해당 없음. 브라우저 기본 `overflow: hidden`이 `border-image`는 자르지 않음(M5, Chromium·Safari 확인). 가상요소에서만 생기던 문제 |
| 얇은 요소(높이 2px `hr`)에서 그림 너비 합이 그림 영역보다 크면 브라우저가 그림을 비율대로 줄여 선이 가늘어지고 밀림 | 그림이 없는 반대쪽 변에 그림 두께만큼 `border-image-outset`을 더 줌 | 적용 (M5에서 발견) |
| 큰 SVG를 변형마다 반복해 CSS가 197KB까지 커짐 | CSS 변수에 한 번 넣고 재사용(65KB로 감소) | 적용 |
| PostCSS는 파일을 따로 처리해, 순번으로 지은 그림 변수(`--sk-1`)가 다른 파일의 다른 그림과 같은 이름이 되어 `:root`에서 덮어씀 | 그림 변수 이름을 그림 내용의 해시로 짓는다 | 적용 (M2 설계 중 발견) |
| `repeat: round`가 소수점 크기 때문에 반복 경계에 이음매를 만듦 | 반복 그림은 늘이지 않음 | 적용 |
| 변형 규칙이 요소별 정밀 규칙을 덮어씀 | 요소별 규칙의 우선순위를 같거나 높게, 순서는 뒤에 | 적용 |
| 빗금 간격이 반복 크기를 나누지 못하면 경계에서 선이 어긋남 | 간격과 반복 크기를 함께 정함 | 적용 |
| 가상요소를 위한 `position: relative`가 `absolute` 자식의 기준을 바꿈 | 가상요소를 쓰지 않음 | 해결됨 |
| `isolation: isolate`가 툴팁을 옆 요소 아래로 가둠 | 가상요소를 쓰지 않음 | 해결됨 |
| `mask-border`와 `mask-image`가 합집합으로 합쳐짐, `mask` 단축 속성이 `mask-border`를 초기화함, 비상속 변수를 가상요소가 못 받음 | — | mask를 쓰지 않아 해당 없음 |
| 테두리 없는 요소(`border: none`, 두께 0)에 거친 단색·형광펜을 쓸 때 | `border-image-width`를 px로 따로 지정하면 그려짐. 바깥 outset도 동작 | Chromium 확인 완료, Safari 확인 필요 |
| 부모의 `overflow: hidden`·`auto`가 바깥으로 나간 선을 자름 | 경고. 부모에 나간 거리 이상의 padding이 있거나, `overflow: clip` + `overflow-clip-margin`이면 안 잘림. 요소 자신의 `overflow: hidden`은 자기 그림을 자르지 않음 | Chromium 확인 완료, Safari 확인 필요 |

## 미정 항목과 이후 과제

MVP 명세를 마무리하려면 아래 항목을 더 정해야 한다.

- [x] 채움 방식을 고르는 방법: 요소마다 `--sketch-fill`로 지정, 기본은 단색
- [x] 테두리 없이 채움만 있는 요소: 일반 요소와 똑같이 처리
- [x] 빗금 끝 기본값: `square`
- [x] 배포 형태: PostCSS 플러그인 본체 + 얇은 CLI
- [x] 지원 브라우저: Chromium 계열과 Safari
- [x] 그리는 구조: A 방식(요소 자체의 `border-image`와 배경, 색 고정)
- [x] 빌드 때 알 수 없는 색: 컴파일 오류
- [x] `border-image`로 표현할 수 없는 경우: 경고
- [x] hover로 그림이 처음 바뀔 때 테두리가 비는지: 문제 없음
- [x] 테두리 없는 요소의 `border-image`: 동작 (Chromium)
- [x] 여러 규칙에 걸친 테두리: 부모를 확실히 알 때만 받아오고, 이름으로만 추정되면 컴파일 오류
- [x] 수정자끼리의 조합: 자동 생성, 용량 예산 경고에 포함
- [x] 뒤집기 변형을 SVG 안 `transform`으로 만들 때의 용량 확인: brotli +27%, 4방향 유지 ("이웃 요소 변형"의 용량)
- [ ] 용량 예산의 기본 수치: 실제 페이지로 보정
- [ ] 세부 다듬기: 선택된 라디오의 점, 텍스트박스 크기 조절 손잡이

이후 버전 과제:

- Tailwind 입력 지원
- 크기를 모르는 요소의 빗금 끝: Houdini `paint()`로 보강
- 요소별 고유 seed: JSX 플러그인, SSR
- headless 브라우저로 실제 크기 측정
- 규칙별 거칠기 덮어쓰기
- CSS 파일 간 그림 중복 제거
- Firefox 지원 (A 방식은 `border-image`만 쓰므로 대부분 동작할 가능성이 큼, 확인 후 공식 지원 여부 결정). 알려진 문제: hover로 그림이 바뀔 때 테두리가 한 프레임 비어 깜빡인다(Chrome·Safari는 없음).
- 그림의 안정성과 버전 정책: 클래스 이름이나 라이브러리 업데이트로 모양이 바뀌는 문제
- 고대비 모드(`forced-colors`) 대응
